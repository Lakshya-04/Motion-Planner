# RViz profiles: description, MoveIt planning, planner backends, self filter

Open any profile with `ros2 launch mp_rviz view.launch.py profile:=<name>` (add `use_sim_time:=true` under a simulator).

**Nothing here was run in RViz.** The profiles were written from the code and from the existing `.rviz` files, and only checked
to be valid YAML with a fixed frame and displays (`python3 -m pytest src/common/mp_rviz/test`). Frames, topics and message types
come from the sources named in each row.

## Topics that were not found

- `curobo_planner`: a C++ client of the cuRobo services. It creates no publisher.
- `curobo_bridge`: `curobo_planner_node` offers only services (`~/plan_joint`, `~/plan_pose`, `~/set_world`, `~/set_esdf`, `~/solve_ik`, `~/check_motion`). No ESDF, obstacle-marker or path topic. The ESDF goes in through the `~/set_esdf` service.
- `vamp_planner`: a plugin library, no publisher, and no launch file.
- ESDF: the only ESDF publisher in the repo is `wall_detector`'s `octomap_esdf_node` (`~/esdf`, `std_msgs/Float32MultiArray`, and `~/esdf_info`). RViz cannot display a `Float32MultiArray`, so there is no profile for it.
- `/ghost/joint_states`: published by `jtac_compliance_demo_node` (with `/joint_states` and the markers on `/jtac_demo/markers`), for the controller demo and not the planners. It belongs to the control profile, which uses the "ghost" TF prefix (`frame_prefix` `ghost/` in the launch file, RViz `TF Prefix` `ghost`). That is not part of these profiles.
- `executed_path` and `/target_robot/robot_description`: see the table.
- `ros2 launch ... --show-args` and the planning-pipeline names for the manager (`planning_curobo.yaml` is named in the curobo README) were not opened.
